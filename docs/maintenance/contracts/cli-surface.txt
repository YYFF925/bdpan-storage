[json]
envelope: code | status | errno | authenticated | data | error | show_msg
upload: data.action = created | renamed | overwritten | unchanged
upload: data.saved_path, data.size
ls: fsid (compat fs_id), path, size, md5 (NON-standard, do not compare with local md5sum)
whoami: expires_at, has_valid_token, is_svip
get-content: status (running | succeeded | partial | failed), task_id, content, url
transfer: task_id, status = submitted, files[].saved_path
auth interruption (3.9.0): data.status (or top-level status) = confirmation_required |
                            authorization_required | upgrade_required — the command did not run
login (3.9.0): code == 0 and data.status == authenticated means usable credentials

[wrapper_contract]
`bdpanw.sh` treats an array as success; otherwise code==0, status in {ok, submitted},
errno==0, or authenticated==true. It trusts the exit code alone for version/logout/completion/
install/update and for any --help call. An auth interruption (see [json]) is always a failure
whatever the exit code, and the payload is passed through unchanged. If a new command returns a
different envelope, fix the wrapper first and run tools/test-bdpanw.sh.
